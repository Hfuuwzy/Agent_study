## 2. ReAct范式 (Reason + Act)

### 2.1 核心思想

**边想边做，动态调整**

模仿人类解决问题：思考指导行动，行动结果反馈修正思考。

**工作流程**:

```
Thought → Action → Observation → Thought → Action → ... → Finish
```

### 2.2 核心组件

#### (1) Thought (思考)

- 分析当前情况
- 制定下一步计划
- 反思上一步结果

#### (2) Action (行动)

- 调用工具: `ToolName[tool_input]`
- 结束任务: `Finish[最终答案]`

#### (3) Observation (观察)

- 工具执行结果
- 作为下一步的输入

### 2.3 应用场景

- 需要外部知识的任务（搜索、查询）
- 需要精确计算的任务（计算器）
- 需要与API交互的任务

### 2.4 特点

**优势**:

- 高可解释性（看到每一步思考）
- 

- 动态规划与纠错
- 工具协同能力

**局限**:

- 依赖LLM能力
- 效率问题（多次调用）
- 可能陷入局部最优

## 3. Plan-and-Solve范式

### 3.1 核心思想

**先规划，后执行**

像建筑师一样：先绘制蓝图，再施工。

**工作流程**:

```
Planning Phase: 问题 → 分解 → 行动计划
Solving Phase:  计划 → 逐步执行 → 答案
```

### 3.2 两阶段设计

#### (1) 规划器 (Planner)

- 接收完整问题
- 分解为子任务列表
- 输出结构化计划

#### (2) 执行器 (Executor)

- 按顺序执行计划步骤
- 维护状态（历史结果）
- 输出最终答案

### 3.3 应用场景

- 多步数学应用题
- 结构化报告撰写
- 代码生成任务

### 3.4 与ReAct对比


| ReAct  | Plan-and-Solve |
| ------ | -------------- |
| 走一步看一步 | 全局规划           |
| 动态调整   | 目标一致           |
| 适合开放任务 | 适合结构化任务        |

## 4. Reflection范式

### 4.1 核心思想

**执行 → 反思 → 优化**

引入事后自我校正循环，像人类一样审视和改进工作。

**工作流程**:

```
执行(初稿) → 反思(评审) → 优化(修订稿) → 反思 → ... → 完成
```

### 4.2 三个关键步骤

#### (1) 执行 (Execution)

- 使用ReAct或Plan-and-Solve生成初稿

#### (2) 反思 (Reflection)

- 独立LLM扮演"评审员"
- 评估维度：事实性、逻辑性、效率、完整性
- 输出结构化反馈

#### (3) 优化 (Refinement)

- 根据反馈修正初稿
- 生成修订稿

### 4.3 迭代优化

可重复进行，直到：

- 反思不再发现问题
- 达到迭代次数上限

```
┌─────────────────────────────────────────────────────────────┐
│                      范式选择指南                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ReAct: 适合需要动态调整、工具交互的探索性任务              │
│          例：搜索最新信息、多轮对话                          │
│                                                             │
│  Plan-and-Solve: 适合结构清晰、可预先规划的任务              │
│                   例：数学题、报告撰写                       │
│                                                             │
│  Reflection: 适合需要高质量输出、可迭代优化的任务            │
│               例：代码生成、文案创作                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
