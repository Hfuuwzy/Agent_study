# 0003 — Run 状态驻留进程内存，事件以 JSONL 落盘，不引入数据库

最初方案为 SQLite 持久化 run 状态以支持进程重启恢复。用户判定产品为一次性使用（每次询问 Agent 都是一次独立 run），重启丢失进行中的 run 可接受，引入 DB（schema/连接/迁移）对本项目是净负复杂度。

决定：run 状态机与事件流驻留**进程内存**（run registry），不做跨进程恢复；每次运行的事件追加写入 JSONL 文件（每行一条事件，含步骤、耗时、工具结果、错误），供失败复查与面试展示真实 trace。若未来需要多用户、重启恢复或审计，再经 repository 接口换存储（当前不实现该接口之外的抽象）。

被否方案：SQLite/Postgres（复杂度与产品定位不匹配）；纯内存不落盘（丢失"失败可复查"的叙事价值）。代价：进程重启丢失进行中的 run——已接受，属于本项目的已知限制，面试时可如实说明。
