# 0001 — 兜底机制保留，但降级运行必须显式标注

原 `MultiAgentTripPlanner` 在任意失败路径都会返回伪造成功计划：`_create_fallback_plan` 为任意城市生成以北京为基准的假坐标与占位景点，API 恒定 `success=True`，用户无法分辨真实数据与降级数据。用户实测发现 Unsplash 对多数城市搜不到图，系统会默认展示北京天坛照片。

决定：**兜底机制保留**（目标：端到端可运行性优先于局部数据真实性），但降级必须成为一等显式状态——响应携带 `status: success | degraded | failed`，降级时列出失败步骤与原因；前端如实呈现而非伪装成功。图片兜底不得展示与目的地不符的城市照片，改用中性占位图或标注"示意图"。

考虑过的替代方案：快速失败返回 500（被否——牺牲可运行性，不符合本项目"优先保证可运行"的目标）；彻底删除兜底（被否——外部 API 超时/空结果时无处安放）。代价：前端需处理多状态渲染（本轮访谈已纳入 scope）。
