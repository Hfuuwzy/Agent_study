# 0003 — Run 状态驻留进程内存，不落盘、不引入数据库

run 状态机与事件流**完全驻留进程内存**（run registry），不写任何文件、不引入数据库。诊断依赖控制台日志（loguru，随 requirements 已存在），运行时在命令行窗口即可看到每一步的问题与耗时。

理由：产品定位为一次性使用（每次询问 Agent 是一次独立 run），用户不需要失败复查/重放能力；写盘行为会引入新增文件与存储位置问题，使项目体积膨胀，与"可运行 + 可讲明白"的实习项目目标冲突。被否方案：SQLite/Postgres（复杂度不匹配）；JSONL 事件落盘（仍属写盘行为，被用户否决）。代价：进程重启丢失进行中的 run，且无法事后复查历史运行——已接受，属已知限制。
