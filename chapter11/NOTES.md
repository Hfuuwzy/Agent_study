## 1. 核心收获

### 1.1 本章的定位转变：从「用模型」到「训模型」

前十章优化的是模型外面的壳（提示词、工具、记忆、上下文、协议），模型本身是固定黑盒；本章打开黑盒，把 LLM 当作**可学习的策略（policy）**做后训练。技术路线：Qwen3-0.6B 基座 → SFT 学任务格式 → GRPO 强化推理策略，数据集为 GSM8K 数学应用题。

**PBRFT vs Agentic RL 的本质差异**（全章最核心的一张表）：传统偏好优化是单步 MDP（`s_0 = prompt`，答完即打分）；Agentic RL 是多步序贯决策——状态随工具调用演化（`s_t = (prompt, o_1, ..., o_t)`）、行动包含文本生成与工具调用、奖励可分步给。这就是为什么 RL 训出来的模型（o1/R1 一类）「天生像 Agent」。

### 1.2 GRPO 的关键简化

PPO 需要 Value Model 估计优势函数，要同时维护 Policy/Reference/Value/Reward 四个模型；GRPO 用**组内相对奖励**替代绝对优势：每个问题采样 `num_generations` 个答案，各自算奖励后减去组内均值得到相对优势，去掉 Value Model，显存和工程复杂度大幅下降。DeepSeek-R1 即由此而来。

### 1.3 奖励函数是 RL 的「宪法」

三种内置奖励（准确率 / 长度惩罚 / 步骤奖励）都以准确率为基底叠加——防止模型为了步骤分生成废话或为了躲长度惩罚故意答错。这个「防奖励黑客」的设计思维在评估任何 Agent 行为时都通用。

### 1.4 SFT 是 RL 的前提

预训练模型输出无结构长文，无法提取答案、无法评估、无法给奖励；SFT 先教会模型结构化输出格式（Step/Final Answer），建立基线并缩小 RL 探索空间。没有 SFT 直接做 RL 几乎必然失败。

### 1.5 工程骨架：四层架构 + 统一入口

数据集层 → 奖励函数层 → 训练器层 → 统一接口层（`RLTrainingTool`）。上层只需组装配置字典调 `run()`（action：train / load_dataset / create_reward / evaluate），返回 JSON。配置外置到 `config.json`（06 脚本的 pipeline 六阶段拆分是可复用的工程模板）。

## 5. 深度思考

1. **对本项目而言，这章的价值是「读懂模型说明书」而不是「学会造发动机」**。日常 Agent 开发走 API 服务时确实用不到自己训练；但商业模型的智能体能力正是这套范式训出来的——理解 Agentic RL 后，选模型、预判短板（哪些模型工具调用稳、哪些爱幻觉）会准得多。
2. **Agentic RL 与前十章构成完整闭环**：ReAct 定义了感知-决策-执行循环，MCP/A2A 打通了工具与协作，而 RL 训练让模型「内化」这些行为而不是靠提示词外部约束。两条提升路径——上下文工程（外）与训练（内）——互补而非替代。
3. **奖励设计的克制比奖励的花哨更重要**：长度惩罚只在答对时生效、步骤奖励以准确率为基底，这些细节体现的是对「目标错位（reward hacking）」的防御意识。做 Agent 评估时同理：指标被钻空子比指标偏低更危险。
4. **学习边界决策**：第十二章及以后的内容（偏底层训练/研究向）超出本项目「面向应用的 Agent 工程」定位，经权衡后学习旅程止于本章。知识储备上，README 已沉淀足够的索引，未来若真需要微调自有小模型，按 README §10.2 的分层路线（升级 → 云 GPU 冒烟 → 完整 pipeline）随时可以续上。
